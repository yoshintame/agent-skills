## База: /extract обязателен

Этот скил — дельта поверх `/extract`. Если `/extract` ещё не загружен в контекст сессии — вызови его через Skill tool **прямо сейчас, до любых действий**: пайплайн, гарды и таблица роутинга живут там, без них дельта неисполнима.

`/rewrite` — структурный maintenance-процесс: перекладка деградировавшего региона. Формула: прочитай всё зафиксированное по региону → **сними старую фиксацию** → выполни `/extract` над знанием как над незафиксированным выводом сессии. Старых файлов «для переноса и правки» в формуле не существует — extract пишет знание в правильные дома с нуля. Ниже — только дельта.

1. **Инвариант доверия — предусловие.** По региону прогнана резолюция (`/actualize`): содержимое правильно и актуально, неправильна только раскладка. Ошибок не ищи — вся ёмкость контекста уходит на структуру; смешивание «найди ошибки» и «переложи правильно» размывает оба фокуса. Дистиллят резолюции (какие ошибки сняты, противоречия в чью пользу решены) держи в контексте — rewrite-по-памяти регенерирует то, что только что вычистили. Без прогона `/actualize` и дистиллята перекладку не начинай.
2. **Обзор структуры.** Прочитай регион целиком; границу держи по связям, не по папке. Ищи структурную деградацию: конфляция ролей (один док = несколько ролей), отсутствующие типы (сущность погребена в теле другого дока), рваность от точечных правок, разбухание (**>500 строк**).
3. **План** — одним сообщением, два обязательных блока; дождись подтверждения перед перетряской:
   - **(а) Целевая раскладка** — дерево файлов/папок по типам и ролям, спроектированное так, как если бы знания региона **нигде не были зафиксированы** и раскладывались с нуля.
   - **(б) Вердикт каждому старому файлу**: `удалить` / `остаётся домом` / `переехать в <путь>`. Файлов региона без вердикта в плане нет. Таблица вердиктов — она же карта для аудита (шаг 6): по ходу исполнения дописывай в неё, какая секция старого файла в какой новый дом ушла.
4. **Исполнение плана.** Целевые доки пиши с нуля чистыми снимками (старые — источник фактов, не черновик); уникальный unit сначала приземли в целевой дом, затем источник **удали** по вердикту — git хранит всё, а страх сноса старого — главный режим отказа перекладки (перенос вместо раскладки, узел-указатель вместо удаления). Расщепление свалки, ретипизация, выпуск погребённых сущностей (Гард 3), переписывание начисто (Гард 4) — частные случаи метода; бэклинки удалённых — де-линкуй или перенацель.
5. **Сверка с планом.** Пройди план шага 3 построчно: каждый вердикт исполнен буквально, каждый целевой док существует и несёт своё знание; отклонение — либо явно обоснуй, либо доделай. FM1-линтер по затронутому; коммить шагами, не одним комом.
6. **Аудит потерь — отдельной сессией.** Своих случайных срезов перекладчик не видит. `/handoff-create` для `/rewrite-audit`: база (коммит до перекладки) и диапазон; карта из шага 3; список осознанных удалений с классом причины (Гард 1, Гард 5, резолвленные open-questions, вводные-клей) — без него аудитор вернёт срезанное как потерю.
7. **Ревью аудита — один круг.** По обратному handoff'у читать только diff коммитов аудита. Каждая восстановленная unit: не пересказ ли кода в спеке (Гард 5); не стала ли оговорка оригинала фактом; тот ли дом по роли. `git show --stat` — не уехал ли файл, грязный до аудита. Лишнее подрезать и закоммитить, спорное — списком владельцу. Второго аудита нет — регион закрыт здесь.
