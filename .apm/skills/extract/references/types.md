# Типы артефактов — справочник роутинга

Спайн effort-management: десять базовых типов плюс подтипы через `extends:`. Роутинг `/extract` кладёт каждый кусок в один из них; здесь — граница «какой именно», когда типы близки. Surface (точное имя `type:`, папка, подтипы инстанса вроде `dev-task` / `dev-project`) — из conventions-скила, не отсюда.

## current-state — гарды применяются

**business-spec** — что система делает в домене (intent, контракт). Источник истины, код выводится из неё.
- Да: поведение и правило домена на языке предметной области.
- Нет: как это реализовано в коде → **implementation-spec** (протёкшая реализация — ошибка типа).

**implementation-spec** — как система построена: только то, чего из кода не видно (Гард 5). Выводится из кода; `kind`: tech / infra / test.
- Да: инвариант, кросс-репный контракт, неочевидное «почему», грабля, схема БД, инфра-субстрат, тестовый канон.
- Нет: пересказ видимого из кода — карта файлов, сигнатуры, разводка, пошаговая сборка (Гард 5); правило домена → **business-spec**.
- Пусто — норма: работа могла не дать ничего невидимого из кода; тогда спеки по ней нет.

## process — время в `status` / `timeline`

**seed** — intent-роль эффорт-цепочки: зафиксированная нужда до проработки. База; инстанцируется подтипами ниже. Роль обязательна, как только работа породила analysis / task / спеку, — либо captured своим seed, либо inherited от upstream (originating-seed рутины, rationale спеки, контекст decision, upstream-task).

**idea `extends seed`** — предложение «надо бы X»: additive intent.
- Да: замысел до проработки — и отложенный, и взятый в работу сразу (роль занимается отдельным артефактом, а не первой секцией analysis).
- Нет: нерешённость → **open-question**; зафиксированный фолт → **problem**.

**problem `extends seed`** — фолт: зафиксированный факт «нечто неправно», corrective intent. Класс, а не эпизод: одна problem порождает сколько угодно манифестаций. Лежать `open` месяцами легитимно.
- Да: любой malfunction — сломалось, сбоит, фейлит, — чей бы код ни был. Ownership решает не это, а бывает ли следом `task`: по своему коду бывает (`kind: bugfix`), по чужому тулу или среде не бывает вовсе, цепочка кончается обходом.
- Нет: разбор причины → **analysis** `kind: investigation` рядом; переиспользуемый обход → **knowledge**; «не знаю как, ничего не сломано» → **open-question**.

**open-question** — нерешённость: развилка / неизвестность / нужен вход извне.
- Да: «не решили, gross или net», «что за процесс на :8002».
- Нет: предложение → **idea** (idea — «сделать бы», open-question — «не решено»).

**analysis** — разбор-груминг, эволюционирует `active → concluded`; `kind`: grooming / investigation / optimization / spec-draft.
- Да: свободная мысль до плана — груминг изменения, расследование причины фолта, genesis-дизайн.
- Нет: «как устроено сейчас» → спека (analysis привязан к ситуации и моменту; спека — вневременной контракт); сам фолт → **problem** (analysis стоит рядом с ним, не вместо).

**task** — юнит работы (план), несёт `timeline` и `due`; дев-подтип — `dev-task` (kind / feature / release).
- Да: есть план, проработка, шаги.
- Нет: одно микро-действие без контента → inline `- [ ]` todo; повторяющаяся обязанность → **routine**.

## event — authored, не переписывается

**decision** — поворотное решение: разворот или отвергнутая альтернатива с причиной.
- Да: только когда несёт контекст за рамками финальной спеки.
- Нет: констатация финального дизайна → спека.

**event** — occurrence: нечто произошло во времени (окно, дата, участники, место). База семьи.
- Да: нейтральное событие — поездка, приём у врача, концерт.
- Нет: плановая встреча → подтип **meeting**; сбой → подтип **incident**.

**incident `extends event`** — адверсный event: impact, хроника, как потушили.
- Да: что случилось и было потушено — occurrence-line.
- Нет: что именно сломано → **problem**, на которую incident линкует полем `problem:` (рестарт закрывает incident, фолт живёт дальше); починка → **task**.

**meeting `extends event`** — плановая встреча; транскрипты отдельными `meeting-transcript`.

## recurring

**routine** — родитель-серия повторяющегося усилия: конфиг повторения, шаблон, накопленное знание. Не завершается, DoD нет.
- Да: регулярная обязанность — бордеран, аренда, декларация, drill.
- Нет: одноразовая работа → **task**; стоячая зона без порождения occurrences → **area**; ограниченная инициатива с DoD → **project**.

Occurrence рутины — типизированный `task` или `project` (по `occurrence-kind`) с `parent` на рутину, никогда не inline-чекбокс. Intent наследуется от рутины — свой seed каждому occurrence не заводится.

## evergreen

**knowledge** — как пользоваться, процессы, онбординг; инструкции для людей.
- Да: «как прогнать релиз», «как вести задачи», переиспользуемый обход фолта.
- Нет: что система делает → **business-spec**.
