Пользователь ревьюит снимки в Chromatic: accept/deny и комментарии остаются там. Читай их скриптами ниже, а не проси пересказ. Принимает снимки только пользователь: `--auto-accept-changes` и accept через API не трогай. Chromatic локально не публикуй, если проект публикует из CI.

Все команды — вне песочницы: нужны сеть до `www.chromatic.com` и запись токена в `~/.local/state/chromatic/`.

## Вход

```
bun ${CLAUDE_SKILL_DIR}/scripts/login.ts
```

Печатает `OPEN <url>` и `CODE <код>` и ждёт до ~15 минут. Отдай пользователю ссылку и код, запусти скрипт в фоне и дождись `TOKEN saved`. Токен — пользовательский OAuth аддона Visual Tests, общий для всех проектов аккаунта; хранится с правами 600, значение не печатай.

Грабли, из-за которых свой скрипт:

- Официального пути нет: CLI `chromatic` только публикует, Storybook MCP и MCP Chromatic облачные ревью не читают.
- Токен проекта (`CHROMATIC_PROJECT_TOKEN`) сборки и тесты не читает — только публикует. Нужен именно пользовательский токен.
- `scope` передаётся только в `/token`. С `scope` в `/authorize` токен читает список тестов, а на комментарии получает `FORBIDDEN`.
- Ошибка `token rejected or expired` — перелогиниться.

## Отчёт по сборке

```
bun ${CLAUDE_SKILL_DIR}/scripts/build.ts <номер-сборки | ветка> [--app <appId>]
```

`appId` берётся из `--app`, `CHROMATIC_APP_ID` или `projectId` (`Project:<appId>`) в `chromatic.config.json` текущей папки — запускай из корня репозитория. Вывод: строка `build N <ветка> <статус>`, счётчики `result/status`, затем каждый не-`EQUAL` тест с тредами: дата, статус треда (`ACTIVE`/`RESOLVED`), сторона снимка (`NEW` — новый, `BASELINE` — прежний) и координаты метки в долях снимка. Номер сборки PR без API не узнать — передай ветку, скрипт возьмёт последнюю сборку.

Треды переносятся между сборками одной истории: старый `ACTIVE`-комментарий виден и на свежем снимке. Сверяй дату комментария с датой своих правок, прежде чем считать его новым замечанием. Комментарий на стороне `BASELINE` — вопрос к базовой ветке, а не к PR.

## Пары «было/стало»

Картинки снимков по API не скачиваются. Пары снимай локально из двух Storybook — базовой ветки и PR, каждый в своём worktree, в фоне:

```
bunx storybook dev -p <порт> --no-open --ci
bun ${CLAUDE_SKILL_DIR}/scripts/pairs.ts <story-id>... --base <порт> --head <порт> [--selector <css>] [--font Verdana] [--out <папка>]
```

`pairs.ts` запускай из worktree проекта: `playwright` берётся из его `node_modules`. Если кэш браузеров пуст — `bunx playwright install chromium`.

Chromatic рисует на Linux: если шрифт проекта не задан или не подгрузился, вместо системного шрифта будет DejaVu Sans, заметно шире SF Pro на маке, и переносы и переполнения в Chromatic локально не видны. Воспроизводи их `--font Verdana`.
